# BAFNet 改进方案 · 官方补充口径

- **基准实验**：`work_dirs/new_data_arfc_only_v1`
- **评分依据**：`比赛评分方案-V1.6-总结.md` §3.1 官方补充口径
- **口径**：先分三大类（舰船/飞机/车辆）算各自 Recall/FDR，再对三大类取算术平均
- **IoU 阈值**：车辆 0.35，舰船·飞机 0.50
- **匹配规则**：score 降序一对一贪心匹配（`tools/eval_recall_fdr.py` 已实现）
- **门槛**：Recall ≥ 85%，FDR ≤ 20%

> 所有指标严格按官方口径由 `test_metrics.json` 的 per-class TP/FP/FN 重算。

## § 2 缺陷根因

### 2.1 数据层 — 跨域漂移 + 极端长尾

- **MS 跨域标注/风格不一致**：MS（民船）是唯一来自三源的高频类 —— 01-PAN (1714)、02-PAN (688)、OTHER (604)，合计 3006 目标，分属不同传感器（`NEW_DATA_REPORT.md §6`）。测试中 R=72.3%、FDR=39.0%，**既漏检又乱报**，典型的跨域分布漂移。
- **极端小样本子型统计无意义**：HM 训练仅 17 个、LQS 仅 43 个；测试集 HM 仅 4 例、LQS 仅 7 例。HM 召回 100% 但 FDR 50%（4 真目标报 8 框），LQS R=57.1%/FDR=66.7% —— 指标波动大、不可靠且易把均值拉偏。

### 2.2 训练层 — BAF 创新模块疑似失效

- **边界损失全程不降（~0.53–0.57）**：`loss_bounder` 从首 epoch 到 ep43 几乎恒定，DSAM + 双边界 GT 这条边界感知支路 **没在学习**。BAFNet 核心创新在本数据上未产生预期收益。
- **ARFC 负载均衡损失恒为 0**：`loss_aux` 全程 `0.0000`。`load_balancing_loss.py` 中 `alpha=0.01` 过小且 `_last_router_logits` 可能未正确缓存，路由均衡毫无梯度贡献 —— **ARFC 多专家自适应沦为名义存在**，存在路由坍缩风险。
- **小目标 AP 近乎为零**：`bbox_mAP_s` 全程 0.04–0.085，而 `bbox_mAP_l` 达 0.738。遥感小目标核心场景（舰船、车辆）未被覆盖，直接对应 QHS/HM/FSC/LQS 低召回。
- **早停过早 + 长平台**：mAP 在 ep35 达峰值 0.680 后连续 8 epoch 无提升，ep43 早停；ep16–43 近 30 epoch 在 0.66–0.68 平台震荡，**后期训练已饱和**，当前增广/正则强度不足，模型早早过拟合到高频飞机类。

### 2.3 推理层 — 阈值配置偏松

当前测试配置（`aircraft_bafnet_1x.py:359-362`）：

```python
rcnn=dict(
    score_thr=0.05,                         # 极低，大量低分框进入结果
    nms=dict(type='nms', iou_threshold=0.5),
    max_per_img=3000)                       # 单图仅 ~5 目标却保留 3000 候选
```

`score_thr=0.05` 是非常激进的低阈值；`max_per_img=3000` 对单图平均 4.94 目标的数据集过大。这是 **飞机高频类与 MS 虚警绝对数偏高**最直接、最易修复的原因 —— 且无需重训。

## § 5 具体改动清单（文件级）

### P0-A：评测脚本输出官方三大类口径（无需重训）

文件：`tools/eval_recall_fdr.py` · `main()` 末尾（约 L363 之后）

```python
# 新增：按三大类分组聚合，输出官方补充口径
def super_of(name):
    if name in ('HM', 'LQS', 'QHS', 'MS'): return 'ship'
    if name == 'FSC':                       return 'vehicle'
    if name.startswith('A'):                return 'aircraft'
    return None

# 按 super_of 把 per-class recall/fdr 分组求均值，再对三大类求均值
from collections import defaultdict
super_r = defaultdict(list); super_f = defaultdict(list)
for row in rows:
    sn = super_of(row[1])           # row[1] = name
    if sn:
        super_r[sn].append(row[5])  # recall
        super_f[sn].append(row[6])  # fdr
super_avg = {s: (sum(super_r[s])/len(super_r[s]), sum(super_f[s])/len(super_f[s]))
             for s in ('ship', 'aircraft', 'vehicle')}
official_recall = sum(v[0] for v in super_avg.values()) / 3
official_fdr    = sum(v[1] for v in super_avg.values()) / 3
# 写入 overall.json 的 official 字段并打印
```

**为什么是 P0**：没有官方口径自动化输出，后续所有实验只能凭「合并口径」自欺 —— 合并口径下召回 92.36% 已过线，会让人误以为只需降虚警。三大类口径才是决赛排序依据。

### P0-B：推理阈值收紧（无需重训）

文件：`configs/bafnet/aircraft_bafnet_1x.py` · `test_cfg.rcnn`（L359-362）

```python
# Before
rcnn=dict(score_thr=0.05, nms=dict(type='nms', iou_threshold=0.5), max_per_img=3000)
# After
rcnn=dict(score_thr=0.30, nms=dict(type='nms', iou_threshold=0.5), max_per_img=300)
```

**验证方式（不重训）**：直接对已有 `test_preds.json` 后过滤 —— 按 `score` 丢弃 `< 0.30`，再跑 `eval_recall_fdr.py` 对比 P0-A 官方口径。进一步可做**按类阈值**：FSC 用 0.20 保召回，飞机高频类用 0.35 压虚警。

### P1-A：MS 跨域专项（需重训）

- **源均衡采样**：`tools/convert_yolo_to_coco.py` 输出 COCO 时保留「源」字段（文件名前缀 01-PAN/02-PAN/OTHER），自定义 `DomainBalancedDataset` 包装器，对 MS 按源等概率采样。
- **copy-paste 增广**：`train_pipeline` 加入 mmdet 自带 `CopyPaste`，将舰船目标粘贴到同源背景，缓解跨域特征漂移。

### P1-B：小目标召回（需重训）

- **高分辨率输入**：`img_scale` (1280,800)→(1280,1024)，启用 `Resize(keep_ratio=True, multiscale_mode='range', multiscale_range=(640,1024))`。
- **排查边界 loss**：`baf.py:322-323` 的 `img_side_gt = fused_gt[:,:3].max(dim=1) > 0.1` —— 特征域拉普拉斯是连续值，与图像域量纲不同，`0.1` 阈值可能把大部分像素判为 0，GT 近全背景、loss 不降。建议特征域分支单独归一化或用软标签。
- **确认 p2 参与**：`RFGenerator strides=[4,8,16,32,64]`，stride=4 的 p2 层应负责最小目标，确认在 `RPNHead` 与 `bbox_roi_extractor.featmap_strides=[4,8,16,32]` 中未被裁掉。

### P2-A：FSC 车辆专项（需重训）

- **类别加权**：三阶段 `bbox_head` 的 `loss_cls` 改为带 `class_weight` 的版本，FSC 权重设为高频类（A16）的 ~5×（2148/428 ≈ 5）。
- **强增广**：FSC 仅来自 OTHER 源，对含 FSC 的训练图额外加旋转（0/90/180/270）+ mosaic。

### P2-B：修复 ARFC 路由坍缩（需重训）

- `load_balancing_loss.py`：`alpha=0.01` → `0.1`。
- 核查 `arfc.py` 的 `GridRouter`：`_last_router_logits` 是否每次 forward 都被 `self._last_router_logits = logits` 覆盖（而非只在某条件分支赋值）。

## § 6 实验与验证节奏

| 阶段 | 动作 | 重训 | 耗时 | 门禁（官方口径） |
|---|---|---|---|---|
| **S1** | P0-A 评测脚本 + P0-B 阈值收紧，对已有 ckpt 后处理验证 | 否 | 2–4h | FDR ≤ 30%，Recall 不低于 73% |

## § 7 预期终态与风险

| 指标（官方口径） | 当前 | S1 后 | S2 后 | S3 后(目标) | 门槛 |
|---|---:|---:|---:|---:|---|
| 整体召回率 | 75.80% | ~74% | ~82% | **≥85%** | ≥85% |
| 整体虚警率 | 34.67% | ~28% | ~22% | **≤20%** | ≤20% |
| 舰船 Recall | 75.22% | ~74% | ~85% | ≥88% | — |
| 舰船 FDR | 46.91% | ~40% | ~30% | ≤25% | — |
| 飞机 Recall | 96.85% | ~95% | ~96% | ≥95% | — |
| 飞机 FDR | 17.56% | ~13% | ~13% | ≤15% | — |
| 车辆 Recall | 55.32% | ~55% | ~72% | ≥80% | — |
| 车辆 FDR | 39.53% | ~35% | ~28% | ≤25% | — |

### 主要风险

- **HM/LQS 极端小样本不可控**：测试集个位数实例，任何改动都让指标大幅波动。建议内部评测时同时报告「剔除 HM/LQS 的舰船均值」作为稳定参考。
- **切片推理时间风险**：1e4×1e4 若需切片，20s 预算可能吃紧。备选测试时降 `rfp_steps` 或用更轻量 backbone 做推理专用分支。
- **阈值收紧 vs 召回的权衡**：P0-B 提阈值降虚警的同时会损失边缘召回（尤其 A15_F-22 这类本就召回偏低的类），需按类精调而非全局一刀切。
- **ARFC 修复后可能反噬**：若路由均衡真的生效，多专家被强制均分，可能降低高频飞机类精度 —— 创新与指标的潜在冲突，需消融实验确认。

**底线**：即使 S3 只部分达成，**S1（阈值收紧）+ S2（MS 跨域 + 小目标）大概率能把官方口径 FDR 从 34.67% 压到 25% 以内、召回提到 82% 以上**。届时即便未完全达 85%/20%，在「7 个排名」二次排序中也将从垫底跃升至中游，为主观分腾出打分空间。
